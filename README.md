# QuestLingua — интерактивная защита исследования

Презентация-сайт для защиты исследования
**“The Impact of Roblox-Based Game Activities on Students’ English Speaking Skills”**
(Yersary Ilyas, Grade 9, School No. 14, Taldykorgan · supervisor Aliyeva Zuhra).

React + TypeScript + Vite + Tailwind CSS + React Router + Recharts + Lucide.

## Публикация на Netlify

**Вариант 1 — через Git (рекомендуется).** Загрузите папку в репозиторий GitHub и подключите его в Netlify
(Add new site → Import an existing project). Настройки сборки берутся из `netlify.toml`:
команда `npm run build`, папка `dist`, Node 22.

**Вариант 2 — вручную.** Выполните `npm install` и `npm run build`, затем перетащите папку `dist`
на страницу https://app.netlify.com/drop. Файлы `_redirects` и `_headers` уже лежат внутри `dist`.

## Локальный запуск

```bash
npm install
npm run dev
```

## Перед защитой

1. Откройте сайт один раз с интернетом — Service Worker сохранит всё в кэш, и дальше презентация
   работает **без интернета** (включая шрифты и демонстрацию).
2. Нажмите **Start Presentation** (или `F`) — откроется полноэкранный режим.
3. Если ноутбук подключён к проектору как второй экран: нажмите `P` — откроется окно докладчика
   (заметки, таймер, следующий слайд). Его можно оставить на экране ноутбука.

## Где менять текст

Весь исследовательский контент отделён от интерфейса и лежит в `src/content/`:

| Файл | Что внутри |
|---|---|
| `project.ts` | название, автор, проблема, цель, задачи, гипотеза, ограничения, практическая ценность |
| `methodology.ts` | дизайн исследования, 5 методов, формат устного теста, 16 сессий |
| `missions.ts` | 8 миссий: цель, целевые фразы, коммуникативное задание |
| `rubric.ts` | 4 критерия и дескрипторы баллов 1–5 |
| `instruments.ts` | анкета, чек-лист наблюдения, вопросы интервью, рефлексия |
| `findYourWay.ts` | карта, маршруты, вопросы и диалоги живой демонстрации |
| `safety.ts`, `references.ts` | безопасность и литература |
| `slides.ts` | порядок слайдов, рекомендуемое время, заметки докладчика |
| `research-record.json` | **проверенные** результаты и подтверждённые сессии |

## Результаты: только проверенные данные

По умолчанию `research-record.json` пуст, и на слайде «Results» показано сообщение
«Verified results have not been entered yet». Никаких цифр сайт не придумывает.

Когда пост-тест проведён и баллы проверены:

1. Explore Mode → **Verified results** → *Enter verified results* — заполните баллы (коды S01, S02…),
   кто и когда проверил, поставьте галочку подтверждения → *Save*.
2. Explore Mode → **Eight-week timeline** — отметьте сессии, которые реально прошли.
3. Эти данные сохраняются только в текущем браузере. Чтобы они были на сайте везде:
   *Export record (JSON)* → замените файл `src/content/research-record.json` → пересоберите/опубликуйте.

Слайд «Conclusion» автоматически формулирует только описательные выводы из этих данных
и всегда напоминает, что без контрольной группы нельзя утверждать причинную связь.
Кнопка «Preview with illustrative data» показывает пример макета с крупной пометкой
**ILLUSTRATIVE DATA — NOT ACTUAL EXPERIMENTAL RESULTS**.

## Важно: проверьте содержание

Исходный документ исследования не был предоставлен, поэтому формулировки цели, задач, гипотезы,
дескрипторов рубрики, вопросов анкеты и интервью, а также содержание миссий составлены по
техническому заданию. Перед защитой их нужно сверить с текстом работы и при необходимости
поправить в `src/content/`. Список литературы — это реально существующие работы по теме,
но окончательным должен быть список из самой работы.
